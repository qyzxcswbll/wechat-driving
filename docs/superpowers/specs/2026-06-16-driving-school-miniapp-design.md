# 平安驾校微信小程序 — 设计规格

## 1. 项目概述

为教练（驾校教练）开发的微信小程序，供学车学员预约参观驾校和预约上课时间，同时为教练提供学员咨询管理和预约审核功能。

**目标用户：** 教练（管理员） + 学车学员
**技术选型：** 微信原生小程序 + 微信云开发（云数据库 + 云函数 + 云存储）
**设计原则：** 简约、易用、一个人即可维护

---

## 2. 页面结构

学员和管理员使用**同一个小程序**，首次打开后微信一键登录，根据 OpenID 自动识别身份并展示对应界面。教练的 OpenID 在 `admins` 集合中标记。

### 2.1 学员端（4 个 Tab）

| Tab | 页面 | 功能 |
|-----|------|------|
| 🏠 首页 | 首页 | 驾校名称/简介/地址、功能入口卡片（了解驾校、预约学车、我的预约、联系我们） |
| 📅 预约 | 预约学车 | 表单：选择日期 + 期望时间 + 科目（二/三）+ 备注，支持添加多个日期一次性提交 |
| 📍 我的 | 我的预约 | 按时间倒序展示预约记录（待确认/已接受/已拒绝三种状态） |
| 💬 联系 | 联系我们 | 显示教练微信二维码（长按识别）+ 复制微信号 + 拨打电话 + 微信客服按钮 |

### 2.2 学员端附属页面

| 页面 | 功能 |
|------|------|
| 了解驾校 | 驾校介绍、地址、联系方式 |
| 预约参观 | 表单：微信昵称（自动）+ 手机号 + 备注，提交后教练主动联系 |
| 预约详情 | 单条预约记录的完整信息 |

### 2.3 管理员端（4 个 Tab）

| Tab | 页面 | 功能 |
|-----|------|------|
| 📊 首页 | 管理首页 | 数据概览：待处理预约数、参观咨询数、已确认课程数；快捷入口 |
| 🙋 咨询 | 咨询学员 | 参观咨询列表，展示学员姓名/手机号/提交时间，可标记"已联系" |
| 📋 预约 | 预约管理 | 上课预约列表，每条可操作：接受 / 拒绝（含原因）/ 微信联系；按日期排序 |
| 📅 课程 | 课程表 | 周视图日历 + 每日课程时间线（已确认的预约） |

## 4. 核心业务流程

### 4.1 参观咨询流程

```
学员填写表单 → 云函数写入 visits（status: pending）
                  → 微信订阅消息通知教练
                  → 教练在"咨询学员"列表查看
                  → 教练通过微信/电话联系学员
                  → 标记为 contacted
```

### 4.2 上课预约流程

```
学员选择日期+时间+科目+备注
  → 支持添加多个日期一次性提交
  → 云函数批量写入 bookings（每条 status: pending）
  → 微信订阅消息通知教练
  → 教练在"预约管理"按日期排序查看
  → 教练点击接受 → status → accepted（加入课程表）
  → 教练点击拒绝 → 输入原因 → status → rejected
  → 微信订阅消息通知学员结果
```

### 4.3 约课限制说明

- 无日期范围限制，学员可预约任意日期
- 无单次数量限制，支持一次性提交多天预约
- 学员可同时有多条待确认 / 已接受的预约
- 拒绝后可重新提交

## 5. 通知机制

使用**微信订阅消息（一次性订阅）**：

| 触发时机 | 通知对象 | 消息内容 |
|---------|---------|---------|
| 学员提交参观咨询 | 教练 | 新参观咨询：学员昵称 + 手机号 |
| 学员提交上课预约 | 教练 | 新预约：学员昵称 + 日期 + 时间 + 科目 |
| 教练接受/拒绝预约 | 学员 | 预约结果：日期 + 时间 + 科目 + 状态 |

用户在操作前调用 `wx.requestSubscribeMessage` 发起订阅授权，授权后通过云调用 `subscribeMessage.send` 发送。

## 6. 技术架构

```

│  原生 wxml + wxss + js + 云 SDK          │
│  pages/student/*  │  pages/admin/*      │

└──────────────┬──────────────────────────┘
               │ wx.cloud.callFunction
               ▼

│           微信云开发                      │

│  │云数据库│  │云函数 │  │ 云存储   │   │
│  │ 4 集合 │  │业务逻辑│  │ 二维码图 │   │
│  └───────┘  └───────┘  └──────────┘   │
```

## 7. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 开发框架 | 原生微信小程序 | 对云开发支持最好，代码体积最小 |
| 后端 | 微信云开发 | 零运维、免费额度足够、原生集成 |
| 身份识别 | 微信 OpenID 判断 | 无需额外登录流程 |
| 预约模式 | 学员自由提交+教练审核 | 最灵活，适合单人排班 |
| 一次性多天预约 | 表单动态添加日期行 | 方便学员批量预约 |
| 学员管理 | 只能查看，不能取消 | 减少纠纷，取消需联系教练 |
| 联系方式 | 二维码+复制+客服 | 三种方式互补 |
| 通知 | 微信订阅消息 | 微信生态内最佳通知方式 |
